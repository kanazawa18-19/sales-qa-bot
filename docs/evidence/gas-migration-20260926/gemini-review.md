# Gemini Pro レビュー原文

会話: https://gemini.google.com/app/28bfcd81b47b51fe?hl=ja

PythonからGASへの移行コード、拝見しました。指定された制約事項（非同期での状態管理、冪等性の確保、Slack POSTの不確実性への対応など）に真っ向から取り組んでおり、特にタイムバジェット管理や古いスレッドの再試行ロジックが非常に丁寧に設計されています。実API検証前に修正すべき、GAS特有の仕様・制限に起因する課題をいくつかピックアップしました。本体の実装バグ（BLOCKER）を中心にまとめましたので、ご確認ください。🚨 BLOCKER (致命的な問題)プロパティストアの書き込み上限・連続アクセス超過再現条件: 過去履歴やスレッド返信数の多いチャンネルを巡回した場合。原因: Main.js の pollSalesQa 内の while ループにおいて、1ステップ（ページネーションやスレッド解析）ごとに props.setProperty(key, JSON.stringify(s)) を実行しています。GASの PropertiesService は書き込みが遅く、1日の呼び出し上限（5万回）や短時間のバースト制限にすぐ到達し、ボットがクラッシュします。最小修正案: ループ内での setProperty をやめ、成功した状態（JSON.stringify(s)）をローカル変数に保持してください。ループを抜けた直後、および例外発生時（catch または finally ブロック）に1度だけプロパティへ書き込む設計に変更します。⚠️ WARN (要修正・パフォーマンス低下リスク)1. 過剰な SpreadsheetApp.flush() によるタイムバジェット枯渇再現条件: AI送信やNotion同期が一度に複数件発生した場合。原因: sync_ や answer_、io.stage 内の各所で flush() を呼んでいます。シートの強制同期は非常に重い処理であり、現在の呼び出し頻度では budget（270秒）をすぐに使い切ってしまいます。最小修正案: SlackやNotionへPOSTする直前（不確実な通信の前に進捗を確定させる箇所）など、冪等性の担保に不可欠な箇所に絞って flush() を残し、それ以外は削除してください。2. Slack APIへの空パラメータ送信再現条件: 履歴や返信の初回取得時（cursor が無い状態）など。原因: slack_ 関数のGETパラメータ生成時、値が空文字（''）のプロパティも cursor=& のようにURLへ結合されます。現在のSlack APIは無視してくれますが、将来的な仕様変更や厳格なバリデーションによって invalid_cursor エラーとなるリスクがあります。最小修正案: Object.keys(args) を map する前に、値が空文字や undefined のものを filter で除外してURLを生成するようにします。ℹ️ INFO (確認・改善推奨)1. 存在しないデフォルトのAIモデル名再現条件: スクリプトプロパティ ANTHROPIC_MODEL を未設定のままAI推論を実行。原因: APIリクエスト時のフォールバック値が 'claude-sonnet-5' となっており、Anthropicの正しいモデル識別子ではありません。最小修正案: フォールバックの指定を 'claude-3-5-sonnet-latest' など、利用可能な実際のモデル識別子に変更してください。2. 外部資料ファイルのメモリ超過リスク再現条件: 数十MBなど、巨大なテキストファイルを SERVICE_MATERIALS_FILE_ID に指定。原因: トークン数（18万文字）のチェック前に .getBlob().getDataAsString() で全内容をメモリ上に展開するため、ファイルが重いとGASのメモリ上限を超えて即座にクラッシュします。最小修正案: 読み込みを実行する前に DriveApp.getFileById(id).getSize() でファイルサイズ（例えば数MB以下か）をチェックし、超過時は安全に停止（throw Error）する処理を追加してください。
